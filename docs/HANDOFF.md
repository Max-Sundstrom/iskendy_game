## 1. Что это за проект

KOMETA — мобильный 3D-раннер для Iskendi: «Поиграть, пока ждёшь заказ». Открывается в iframe с карточки «Сыграть».

- **Гости:** без входа, без сервера и без рейтинга в v1 (ADR-016/019/020).
- **Конец забега:** авария заканчивает забег. Экран итогов показывает счёт, «Ещё раз» и промокод, который ничего не даёт.
- **Механика** взята из референса (Tesla/SpaceX-тематика) и записана в `docs/GDD.md §1`.
- **Внешний вид оригинальный:**
  - машина Kometa R, концепт B «Samodelka»;
  - город Kometograd;
  - ливрея Iskendi Courier.

### Репозитории

| Репозиторий | Что в нём |
|---|---|
| `Max-Sundstrom/iskendy_game` | Игра. Работа идёт здесь. |
| `Max-Sundstrom/iskendy-frontend` | Фронт Iskendi (хост). По игре: `docs/53-game-kometa.md`, `docs/10-decisions.md` (Q-33, Q-37). Правила — его `CLAUDE.md`/`AGENTS.md`: без одобрения не пушить в `main` основного репо и не трогать бэкенд. |

### Стек

- pnpm 12 workspace: `apps/web` (игра), `apps/lab` (дизайн-лаборатория, не отгружается), `packages/{sim,shared,content}`.
- TypeScript strict, three.js 0.186, zod 4 (`jitless` из-за CSP), Vitest, Playwright.
- Симуляция детерминированная: 60 Гц, sfc32, LUT вместо трансцендентных функций (`packages/sim`).
- Рендер только читает снимки симуляции (`apps/web/src/engine`).

## 6. Как работать в этом окружении

- **pnpm 12** через Corepack не запускается:
  - поставить так: `npm i -g pnpm@12.11.2` (или в свой префикс);
  - pnpm 12 не читает `.npmrc`, настройки лежат в `pnpm-workspace.yaml`.
- **Проверки:**
  - `pnpm typecheck && pnpm lint && pnpm test`;
  - `pnpm format` (Prettier);
  - `pnpm build && pnpm check:size` (бюджет JS 400 КБ gzip, сейчас около 190 КБ).
- **e2e:** `PW_CHROMIUM_EXECUTABLE=/opt/pw-browsers/chromium npx playwright test`.
  - Dev-сервер `http://localhost:5173` запускается сам.
  - Без GPU рендер очень медленный, поэтому в тестах `?q=low`.
  - `?intro=0` пропускает рампу.
  - `?seed=N` фиксирует сид.
- **Отладочные страницы dev-сервера:**
  - `/test/models.html?view=rear|side|front` — галерея всех моделей;
  - `/test/determinism.html`, `/test/replays.html`.
- **Data-атрибуты `#app` для e2e:** `data-screen` (intro/playing/results), `data-distance`, `data-lane`, `data-flip`,
  `data-air`.
- **Замер:** `#perf` в URL показывает p50/p95, число draw calls и треугольников. Бюджеты — ARCHITECTURE §12: ≤ 150 draws,
  ≤ 300k треугольников. Сейчас в забеге 116 draws и 138k.

## 7. Правила, которые легко нарушить

- **Симуляция** (`packages/sim`): без DOM, three.js, `Math.random`, `Date`, `sin/cos/pow…` — ESLint это ловит.
  - Новое поле состояния добавлять в `hash.ts`.
  - Новое событие — в конец `SimEventKind` (`packages/shared/src/events.ts`), без перенумерации, с декодером в
    `packages/sim/src/events.ts`.
- **Изменились исходы симуляции:**
  1. `npx tsx tools/make-golden-replays.ts`;
  2. новый `GOLDEN_10K` в `packages/sim/src/determinism.test.ts` **и** в `e2e/determinism.spec.ts`;
  3. строка в DECISIONS → Sim changelog с причиной (ADR-024; `SIM_VERSION` остаётся 1 до релиза).
- **Тюнинг:** любые игровые числа только в `packages/content/tuning.default.json` со схемой в
  `packages/shared/src/tuning/schema.ts`.
- **Трафик:** каждая модель ≤ 3000 треугольников (тест `models.test.ts`). Хватает `TRAFFIC_DETAIL` в лофте.
- **CSP:** без inline-стилей и `eval`/`new Function`. Стили только в `src/style.css`. Smoke e2e падает на любом нарушении CSP.
- **Зависимости:** версии старше 14 дней, точные (`saveExact`), новые — только с одобрения владельца.
- **Безопасность:** не коммитить секреты и `.env`, не ослаблять и не удалять тесты, одобрения владельца не записывать за
  него.
- **Тексты для игрока** — в `packages/content/i18n/{ru,en}.json` (русский по умолчанию).

## 8. Грабли, на которые уже наступали

- `pkill -f`/`pgrep` по шаблону с `node` убивает собственный shell. Использовать `pgrep -f '[n]ode.*/vite'` отдельной
  командой.
- Docker Hub отвечает 429: брать образ через `mirror.gcr.io` с тем же digest.
- Первый кадр `requestAnimationFrame` может дать отрицательный `dt`, поэтому в `main.ts` стоит `Math.max(0, …)`.
- Нажатие прыжка в воздухе — это сальто, кроме случая, когда до дороги меньше `jump.bufferS` (буфер, сценарий G3;
  DECISIONS Q21).
- В медленном headless два нажатия подряд могут слиться в одном кадре. В e2e ждать `data-air="1"` перед вторым нажатием.
- `mergeByMaterial` в `car.ts` склеивает детали машины по материалам ради бюджета draw calls. Новая деталь с текстурой
  (`map`) остаётся отдельным мешем.
