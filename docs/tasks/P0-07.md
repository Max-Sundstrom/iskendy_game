# P0-07 — Security baseline
Owner: Security engineer (done by the Orchestrator session) · Reviewers: code-reviewer · Phase: 0 · Depends on: P0-01, P0-02

## Goal
Secrets, unsafe code patterns and vulnerable dependencies are caught on every push; supply-chain and header
rules are in place before product code exists.

## Context
ROADMAP P0-07; SECURITY §3 (T12–T18), §4, §7; TEST_STRATEGY §4; INFRASTRUCTURE §0, §4.

## Scope
`.github/workflows/security.yml`, CI trigger, `tools/semgrep/`, `tests/fixtures/semgrep/`, `.semgrepignore`,
`renovate.json`, `deploy/Caddyfile`, `tests/security-headers.test.ts`, `docs/runbooks/github-settings.md`,
SECURITY §4, DECISIONS.

## Out of scope
Applying repository settings (owner), the container image and preview deploys (P0-08), ZAP/ASVS (P7-06).

## Acceptance criteria
1. CI shows gitleaks, Semgrep, CodeQL and OSV-Scanner checks; all green on the current code.
2. Each project Semgrep rule fires on its fixture and stays quiet on the clean fixture.
3. Third-party tools are pinned: actions by SHA, the binary by sha256, the image by digest, all at least 14 days old.
4. Renovate is configured with a 14-day minimum release age.
5. The CSP/header skeleton exists, is tested, and frames only the Iskendi host.
6. Branch protection and the code-security settings are documented for the owner.

## Verification
Local: `pnpm typecheck && pnpm lint && pnpm test && pnpm format:check`, gitleaks over the history, Semgrep
project rules + fixture check, `caddy adapt --validate`, headers from a local Caddy serving the build.
Remote: first run of `Security` and `CI` on the branch.
