# P0-03 — Tuning schema, loader and tuningHash
Owner: Sim engineer (done by the Orchestrator session) · Reviewers: code-reviewer, qa-engineer · Phase: 0 · Depends on: P0-01

## Goal
Every gameplay number is validated before use (invariant 3), errors point at the exact key, and replays can carry
a hash of the sim-relevant tuning.

## Context
ROADMAP P0-03; AGENTS §6 inv. 2–3, 10; ARCHITECTURE §4.4, §4.7; `packages/content/tuning.default.json`.

## Scope
`packages/shared/src/tuning/`, `packages/shared/src/index.ts`, `packages/sim/src/{index,tuning}.ts` and tests,
package manifests (zod), tsconfigs, ARCHITECTURE §4.7, DECISIONS pinned versions.

## Out of scope
Changing any tuning value; runtime tuning overrides; the replay format itself (P1-06).

## Contract
`parseTuning(raw): Tuning` (throws `TuningError` with `problems: string[]`), `tuningHash(sim): string`
(16 hex), `canonicalJson(value)`, schemas `TuningSchema` / `SimTuningSchema` / `PresentationTuningSchema` /
`ServerTuningSchema`; `@kometa/sim` exports `DEFAULT_TUNING`, `DEFAULT_TUNING_HASH`. Frozen: no (P1 may add keys).

## Acceptance criteria
1. The shipped tuning loads through the schema.
2. Invalid tuning fails with a readable, path-level error listing every problem (bad value, unknown key,
   missing key, array index, cross-field rule).
3. `tuningHash` covers the `sim` section only, ignores key order, changes when any sim number changes, and
   is pinned by a golden value.
4. Shared and sim sources compile without DOM or Node types.

## Verification
`pnpm typecheck && pnpm lint && pnpm test && pnpm format:check && pnpm build`.

## Handoff note
- **What changed:** strict zod schemas for `sim`, `presentation` and `server`, with ranges and cross-field rules:
  minMps ≤ maxMps, startL ≤ capacityL, ordered landing grades, ring line min ≤ max, rows only get denser,
  wave min ≤ max, at least one free lane, biomes sorted from 0 m, FOV min ≤ max, buttons ≥ 44 px.
  `parseTuning` + `TuningError`. `tuningHash` = FNV-1a 64 over canonical JSON, with BigInt and a hand-written
  UTF-8 encoder, because `TextEncoder` is not available without DOM/Node types. The sim validates the shipped
  file at module load.
- **Verified:** all checks exit 0; 22 tests in 5 files, including fast-check properties (every sim number
  changes the hash; UTF-8 encoder = Node's for any valid string). Golden `788ecccb429e4cdc` reproduced by an
  independent Python FNV-1a 64 over the same canonical JSON. Mutation: `z.object` instead of `z.strictObject`
  for `jump` fails the misspelt-key test. Sample error:
  ```
  Invalid tuning:
    - sim.speed.maxMps: Too small: expected number to be >0
    - sim.speed.minMps: minMps must not exceed maxMps
    - sim.jump: Unrecognized key: "apexHeightMeters"
    - sim.air.canisterL: Invalid input: expected number, received undefined
  ```
- **Notes:** package tsconfigs now exclude `*.test.ts`; the root tsconfig checks tests with Node types.
  `@kometa/shared` gets `@kometa/content` as a dev dependency (test data only). The web bundle grew to 27.75 kB
  gzip (zod + tuning), well inside the 400 KB budget; `zod/mini` is an option if size gets tight.
- **Tuning keys / SIM_VERSION:** none added / unchanged (1).
- **Follow-ups:** P1-01 uses `DEFAULT_TUNING`; P1-06 puts `DEFAULT_TUNING_HASH` into replays.
