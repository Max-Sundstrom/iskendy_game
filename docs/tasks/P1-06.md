# P1-06 — Replay recorder/player, replay:verify, golden replays across engines
Owner: QA engineer (done by the Orchestrator session) · Reviewers: code-reviewer, security-engineer · Phase: 1 · Depends on: P1-05

## Goal
Every run can be reproduced bit for bit from its input log, in Node and in every browser engine, and tampering
shows.

## Context
ADR-002; ARCHITECTURE §4.4, §4.7; SECURITY T1, T2, T10; AGENTS §5 (`replay:verify`), §8 (goldens).

## Scope
`packages/shared/src/replay.ts`, `packages/sim/src/{replay,version}.ts`, `tools/{make-golden-replays,replay-verify}.ts`,
`tests/replays/*.json`, `tests/replays.test.ts`, `apps/web/src/{game/session.ts,platform/replays.ts,main.ts}`,
`apps/web/test/replays.*`, `e2e/replays.spec.ts`, Playwright cross-engine projects, CI job `cross-engine`.

## Contract
`Replay` (schemaVersion 1; seed, tuningHash, ticks, inputs as [tick, mask] on change, claimed score/distance,
finalHash); `parseReplay(text, limits)` (size cap, prototype keys rejected, zod); `createRecorder`, `playReplay`.
Frozen: yes for v1 (changing it bumps `schemaVersion`).

## Acceptance criteria
1. Goldens reproduce in Node, Chromium, WebKit and Firefox.
2. `pnpm replay:verify <file>` prints hash and score and exits non-zero on a mismatch.
3. Tampered score, inputs, version or tuning are detected; oversized or prototype-polluting payloads are refused
   before simulating.
