# P3-00C — Make actual crashes readable

Owner: render / UI engineer · Reviewers: independent QA and visual review · Phase: 3 · Depends on: P1-09, P0-09

## Goal

Show a clear, short response to an actual simulated collision before results cover the car.
The run ends at its original deterministic crash tick; presentation must never change its outcome.

## Context

Owner requested a visible collision response after model improvements. GDD §5, §13, §15.4; scenarios J12/J14,
P1; ART_DIRECTION §7; ARCHITECTURE §12. Currently results cover the first crash frame, wheels and continuous
thrusters can keep moving, and Retry leaves particle/emission/camera state behind.

## Scope

`apps/web/src/main.ts`, `engine/{renderer,crash,camera,thrusters,vapour}*`, a small `game/` presentation controller,
a reduced-motion platform adapter,
small UI collision cue, i18n strings, stylesheet, presentation-only tuning/schema fields and focused tests.
No changes to `car.ts`, traffic models, perf collector/runner, input adapter, sim or its hashes/goldens.
Wait until P0-09 releases main/style ownership; branch from that completed card before implementation.

## Contract

- `CarRig` stays unchanged; models are a separate card.
- Sim status/event is the sole crash trigger. `crash.cause` is rear/secondScrape/landing; no contact point is supplied.
- Main owns intro/playing/crashing/results, stops stepping at the crash tick, clears controls and records the result once.
- A one-shot presentation controller advances only while visible. Renderer consumes its read-only pose/progress;
  render frames must not replay the retained sim event buffer. Results follow the brief response.
- Recoil/settle, duration and burst tunables belong to `presentation`, never the hashed `sim` section.
- Effective reduced motion is the OS preference OR an explicit supplied preference. There is no existing settings
  store or saved key to guess. Support the future preference input without creating a new settings screen here.
- Reduced motion uses a static readable cue and omits camera shake, FOV kicks and animated impact recoil/flash.
- Retry resets pose, spin, camera smoothing, particles, emission carry and glow; hidden time must not advance effects.

Concrete API frozen: `RunScreen = 'intro' | 'playing' | 'crashing' | 'results'`;
`CrashFrame = Readonly<{ elapsedS: number; deltaS: number; reducedMotion: boolean }>`;
renderer gains `beginCrash(session)`, `renderCrash(frame)` and `reset(session)`.
Initial `presentation.crash` defaults: durationS .75, settleDurationS .25, bodyDropM .06, bodyPitchDeg 6,
cameraPullbackM .18, cloudCountPerNozzle 8, cloudLifeS .45, cloudSpeedMps 2,
cloudSpreadMps 1.5, cloudSizeM .25, cloudGrowM .8, cloudAlpha .35.
These are presentation defaults, not the four deferred gameplay tuning proposals.

## Acceptance criteria

1. An actual collision shows a bounded local car response and appropriate low-intensity impact cue, then results.
2. Crash while boosting/flying stops continuous thrust and wheel spin. Each crash triggers one response and one result.
3. Landing and rear/side collision causes are handled without fabricated collision coordinates or changing sim physics.
4. Hidden/resumed tab, repeated frames, Retry twice, keyboard/touch and reduced-motion paths remain correct.
5. No rapid flashing, inline style, new dependency, per-frame allocation or unbounded particle growth.
6. Unit and browser regression evidence includes interrupted/repeated paths. Sim/goldens stay unchanged.
7. Real browser screenshots at both viewports show impact and results, including reduced motion; independent reviewer
   inspects the images. `perf:smoke` geometry gates pass and reports headless timing as informational only.

## Verification

Typecheck, lint, format, unit, sim, build/size, relevant production browser/CSP checks and perf reports.
Record every unrun or unsupported check. Publish a separate draft PR; no automatic merge/deploy.

## Handoff note

- Implemented explicit intro → playing → crashing → results flow. The result/replay/promo is captured once at the
  original crash tick; the .75 s interval uses visible time only. The sim and recorded input masks are unchanged.
- Presentation freezes world/wheels/thrust, uses a single .25 s compression/nose-dip/settle and a short local gas
  cloud from real nozzle anchors. No collision point/normal is inferred. The initial .06 m compression alone was
  too subtle in actual desktop screenshots; independent visual review requested the bounded 6° pitch.
- Landing crashes retain the preceding sim tick's actual flip angle because grading resets `flipTurns`. This has
  at most one 60 Hz tick of lag; it is not claimed to be the exact touchdown angle. Other crash causes use the
  terminal orientation. No simulation, golden replay, determinism fixture or SIM_VERSION changes were needed.
- OS OR an explicit typed future preference removes crash motion, particles and existing speed/boost FOV. No
  guessed saved preference or new settings UI. Live changes and frozen-camera resize update projection only.
