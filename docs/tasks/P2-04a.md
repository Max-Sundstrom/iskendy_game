# P2-04a — Automatic LIFTOFF, SMASH and safe expiry

Owner: sim engineer · Reviewers: independent QA and orchestrator · Phase: 2 · Depends on: P2-03b

## Goal and scope

Implement the first playable mode slice from GDD §§5–6, 9–10: a full style meter starts five seconds of
LIFTOFF with actual collision destruction, unlimited usable AIR, the existing speed multiplier and safe
expiry. This card does not complete P2-04: COSMONAUT, OVERDRIVE and pickup triggers follow separately.
The full HUD and rocket/VFX remain P2-07/P3-07. No new dependencies or changes to main, the stable phone
preview, owner-pending tuning proposals or car design.

Sim author owns packages/sim, packages/shared, packages/content/tuning.default.json, focused sim tests,
golden and determinism fixtures, and this card's design/evidence documentation. Presentation waits for
the implemented TypeScript contract and a separately assigned author. Browser/perf runs are scheduled
by the orchestrator, with one heavy browser run at a time.

## Proposed implementation contract — awaiting confirmation

The following implementation boundary was prepared on 2026-10-26. The parent explicitly requires
confirmation of the disputed mode rules before implementation; no source changes are authorized yet.
Product defaults below are proposals for `sim.modes.liftoffEnabled=true`, not owner design signoff.
Record the policy bundle as Q28 in DECISIONS and describe it in GDD. False preserves previous gameplay.
Keep existing numeric durations, speed factor and score values in tuning unchanged.

1. Add shared ModeKind none=0/liftoff=1 and SimState.mode with kind, activeTicksLeft, graceTicksLeft and
   smashChain. Hash every persistent field. Append events modeStarted=27 (a kind, b active ticks),
   modeEnded=28 (a ended kind, b grace ticks), modeGraceEnded=29 (unused payload), smash=30 (a vehicle
   type, b one-based episode chain index); append ScoreReason.smash=12. Append explicit RideEnd.smashed
   and its decoder. Never dereference a removed traffic slot from a presentation event.
2. Physics uses the phase present at tick start. Movement/contacts/landing → score and settlement →
   retire one tick from the starting phase → auto-trigger when now idle and running. The trigger tick
   is ordinary; the next 300 ticks are active, then 60 grace ticks. Never decrement a newly created
   timer or revive a same-tick crash. A full meter on the last grace tick can trigger the next episode.
   Reserve the future OVERDRIVE extension position before active timer retirement, without adding a
   speculative hook or implementing stacking in this card. Manual autoTrigger=false only holds meter.
3. Active mode allows flight/boost even at stored AIR zero. Freeze the finite tank during active mode
   (no drain and no regeneration); never store Infinity. Grace resumes normal bookkeeping. Compose
   the existing LIFTOFF speed factor with boost and existing penalty, without erasing penalty history.
4. Dispatch active contact before ride/HOP/scrape/crash mutations. Each contacted live vehicle, including
   static hazards and the starting ridden support, is removed once, invalidates CLEAR/near trackers,
   increments the episode SMASH index and emits one smash in deterministic slot order. Actual descent
   onto a roof is contact; clear flight above it is not. A destroyed roof creates no HOP/ride/landing or
   synthetic STUNT. Continue vertical motion/SLAM until actual road touchdown. Detach a still-ridden
   support at its current height, with no coyote privilege; preserve a jump already launched from it.
5. Active and global grace road landings auto-right and grade STUNT exactly once, including jumps with
   no completed trick. Test this before the existing no-trick early return. Reset both axes and queues;
   retain completed-trick events. No new landing penalty. Expiry cannot immediately cause a landing
   crash during grace. After grace, a per-vehicle phase latch gives no global landing protection.
6. Grace is protection only: no extra speed/AIR, no destruction or SMASH credit, no new roof support.
   Contact invalidates that vehicle's CLEAR/near encounter. Add a per-slot Uint8 phaseUntilExit latch,
   hashed for active slots, cleared on reuse/removal/new run. Capture closed AABB overlap/tangency at
   grace expiry; phase the same vehicle until complete separation, forgiving the exiting step before
   clearing the latch. New/unlatched vehicles still collide normally after grace. A new mode clears
   old latches and SMASH takes precedence. No coordinate history requiring origin-shift rebasing.
7. SMASH scoring uses min(cap, base + step * (index - 1)) through the existing action ledger; meter
   gain is zero, streak N rises once and timer refreshes. Chain resets only on a new mode episode.
   Preserve producer order/settlement precedence; re-prove event capacity including mode events.
8. While OVERDRIVE is absent, meter may fill during active/grace and remains saturated until idle.
   No hidden manual binding, pickup or extension is invented. Future mode kinds append numeric IDs.

## Acceptance and independent verification

- Exact trigger/active/grace boundaries, zero configured grace, last-tick meter gain and same-tick fatal
  collision; active AIR zero/freeze/release/expiry, boost and penalties; non-trick and unsafe landings.
- Rear, first/second scrape, static hazard, roof SLAM, existing ride and jump-off support SMASH; no
  duplicate landing/HOP/CLEAR/near award; 64 contacts and chain cap, bounded event buffer.
- Grace overlap exit/re-entry, closed tangency, slot reuse/removal, origin shift, unlatched collisions,
  new episode, paused/no-step state, Retry, interleaved sessions and future-state hash distinctions.
- Flag-off comparison against immutable P2-03b on three golden trajectories and both 10k fixtures;
  explain all default-on changes before updating goldens, BOTH fixtures and Sim changelog. Retain
  SIM_VERSION 1 only under ADR-024. Add scenario G24; never weaken existing assertions.
- Prove at least one unchanged-default seed and actual input log earns the full meter, activates mode,
  makes a real SMASH, expires and reaches a reproducible terminal outcome. No lowered thresholds,
  state injection or fabricated event can stand in for this route. Browser and visual evidence follow
  only after this route is independently verified.
- Full relevant typecheck/lint/format/unit/sim/build/size checks and exact-head cross-engine CI. The
  inherited PR4 desktop timeout is tracked separately and must not be reported as mode acceptance.
