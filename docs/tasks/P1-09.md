# P1-09 — Preserve quick input edges across simulation steps

Owner: UI engineer · Reviewers: independent QA, code reviewer · Phase: 1 · Depends on: P1-05, P2-02 part 1

## Goal

Fix the reproduced desktop double-Space failure on P2 head `5a16989` without weakening the existing browser test.

## Context

GDD §4, §5.6; scenarios G2/G3 and P1; CI run 40022120269, desktop `e2e/run.spec.ts:102`.
The frame-level input latch can hide a release between successive presses from the fixed-step simulation.

## Scope

`apps/web/src/input/*`, `apps/web/src/game/session*`, `apps/web/src/main.ts`, focused regression tests,
`e2e/run.spec.ts` observer timing and this card. No simulation rules, tuning, dependencies, security or visual
design changes.

## Contract

Frozen: the sim still consumes one held action mask per tick and derives rising edges using `prevHeld`.
The input adapter must preserve release/press ordering across ticks, including multi-step and zero-step frames.
Record the actual mask used by every tick so replays reproduce the resulting game.
Keep support for constant-mask callers of `advance`; any additional tick-input source is presentation-only.

## Acceptance criteria

1. Desktop and mobile double-tap/Space checks retain their jump/airborne and positive-flip requirements and
   10-second timeout. Observation timing may change to avoid missing a transient rendered state.
2. Two quick presses separated by a real release remain two sim edges even with no intervening render frame.
3. Held jump/boost remains held; repeated keydown does not add presses; releaseAll discards pending input on blur/retry.
4. Regression tests cover zero-step/multi-step frames and replay round-trip with the input adapter.
5. Typecheck, lint, format, unit/sim, build/size and browser checks pass; record actual results and limitations.

## Handoff note

- **Production fix:** the frame-level latch collapsed quick release/repress into a continuous hold. Controls now
  preserve pending press edges per simulation tick, insert the required release tick, retain continuous holds,
  and clear queued input on interruption. Session advancement samples only ticks actually executed and records
  each exact mask. Numeric-mask callers remain supported; sim rules, tuning, version and goldens are unchanged.
- **Browser diagnosis:** first failing trace showed flip angles 0.30 and 0.45 before a Node-side locator read
  returned after touchdown reset. Arming `waitForFunction` with `Promise.all` also failed: its API call began at
  12969.003 ms, the second Space at 12969.635 ms, and a later snapshot at 13962.136 ms showed a real 0.30-turn
  rotation. The trace has no predicate-invocation timestamps. Installed Playwright initializes its main-world
  helper asynchronously before polling, so API invocation order did not guarantee observer readiness. The
  exact callback delay cannot be proved from this trace; this was an uncontrolled observation/setup race.
- **Validated test:** pause the Playwright browser clock before navigation and advance real animation frames
  with `runFor`. Keep the real keyboard/touch adapters, sim and renderer. The first press must jump with zero
  flip; the second must produce a positive rendered angle; then the complete flip must land upright while the
  run remains playing. The original positive-angle threshold and 10-second deadline remain. Desktop additionally
  proves two trusted Space events, default prevention, BODY focus and no focused Retry button. All other E2E
  journeys run on the normal browser clock. No production diagnostic latch or direct sim manipulation was added.
- **Independent checks:** full typecheck, lint/boundaries, format, 143 unit tests, 56 sim tests, assets,
  build/size passed (192.3 KiB JS gzip / 400 KiB budget). After the final E2E change its typecheck/lint/format
