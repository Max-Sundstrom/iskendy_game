# P0-08 — Game container, kill switch, release archive (v1 environments)
Owner: Release engineer (done by the Orchestrator session) · Reviewers: security-engineer, code-reviewer · Phase: 0 · Depends on: P0-02, P0-07

## Goal
What ships to `play.iskendy.ru` is built, checked and packaged by CI. The game can be switched off without a
host deploy. A person can deploy and roll back from a runbook.

## Context
ROADMAP P0-08 (v1 row); ADR-021; INFRASTRUCTURE §0, §4; EMBEDDING §2; SECURITY §4; Q17/Q18 (no error or
metrics stack in v1).

## Scope
`deploy/` (Dockerfile, Caddyfile, disabled page), `.dockerignore`, `tools/{check-headers.ts,pack-release.sh,embed-e2e.sh}`,
`e2e/` (smoke CSP check, embed spec, mock host, tsconfig), CI `container` job, `release.yml`, runbooks, docs.

## Out of scope
Per-PR preview URLs: they need a host decision (GitHub Pages or the Iskendi server); the CI `container` job and
the per-push archive artifact cover review for now. Server setup (owner).

## Acceptance criteria
1. The release archive builds with a checksum, reproducibly, and the container builds from the unpacked archive.
2. The container serves the game with the SECURITY §4 headers, runs as non-root and has a healthcheck.
3. `KOMETA_MODE=off` makes the host receive `game.error { code: 'disabled' }`.
4. CI proves 2–3 against the real image, and E2E fails on any CSP/Trusted Types violation.
5. Deploy, kill-switch and rollback runbooks exist.

## Verification
Local (Docker in the cloud container, Caddy image via `mirror.gcr.io` with the pinned digest): `tools/embed-e2e.sh`.

## Handoff note
- **What changed:**
  - Dockerfile and Caddy modes;
  - disabled page, with the host origin filled by Caddy templates and no wildcard `postMessage`;
  - header checker; reproducible pack script; embed E2E with a mock host on a second origin;
  - CI `container` job; release workflow (artifact per main push, GitHub Release on `vX.Y.Z`);
  - smoke test collects `securitypolicyviolation` events and page errors;
  - Trusted Types enforced; three runbooks.

  a Trusted Types violation even though zod catches it. Fixed with `z.config({ jitless: true })` in
  `@kometa/shared`.
- **Verified:**
  - typecheck/lint/format, 36/36 unit tests;
  - `tools/embed-e2e.sh` → headers OK and 6/6 E2E (smoke ×2, host frames the game ×2, kill switch ×2);
  - dev-server E2E 2 passed, 4 skipped (embed specs need containers);
  - the archive packs twice to the same sha256 (`64a0afc5…` for the same build) and the image builds from
    the unpacked archive;
  - container `id` → nobody; mutation: appending an `insertAdjacentHTML` call to `main.ts` fails the smoke
    test with "enforce require-trusted-types-for".
- **Review (self):** the release job had `contents: write` while it ran `pnpm install`; publishing moved to a separate job that only downloads the artifact, checks its sha256 and creates the release.
- **Notes:** Docker Hub rate-limits shared IPs, so CI pulls the same digest from `mirror.gcr.io`. Port on the
  server is 127.0.0.1:8090 behind the shared Caddy.
