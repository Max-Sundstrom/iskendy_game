# P2-04a1 — Deterministic LIFTOFF clock foundation

Owner: sim engineer · Reviewers: independent QA and orchestrator · Phase: 2 · Depends on: P2-03b, P2-04 design

## Goal and boundary

Implement the agreed timing primitive from GDD §10 without selecting the unresolved product policies in
PR #9. Default LIFTOFF is five seconds and the following grace interval is one second, measured in fixed
simulation ticks. This is an internal foundation, not a playable or activated mode.

The owner has been asked the minimal R1–R5 policy bundle. No answer has been received. AIR bookkeeping,
roof destruction/rewards, grace landing/overlap behavior and the SMASH chain remain unimplemented.
No change to live step(), SimState, score, collision, hash, tuning, goldens, either existing determinism
fixture, production UI or preview is allowed in this card. Later integration must hash persistent mode
state and meet all replay and browser requirements. No main merge, deployment or dependencies.

## Frozen technical contract

Own `packages/sim/src/mode-clock.ts`, its focused tests, and this card's evidence. The module is deliberately
not wired into the running game. It may use validated SimTuning but no clocks, randomness, allocations per
tick, browser imports or transcendental math.

- `ModeClock` has finite integer `activeTicksLeft` and `graceTicksLeft`, initially zero, with at most one
  positive counter. Allocate it only in `createModeClock()`; use numbers rather than wall-clock timestamps.
- `startLiftoffClock(clock, tuning)` starts only an idle clock, assigning
  `ceil(tuning.modes.liftoff.durationS * tuning.tickRateHz)` active ticks. It returns whether it started;
  a second start during active/grace is a no-op. It does not inspect, consume, retain or reset the meter.
- `advanceModeClock(clock, tuning)` consumes exactly one existing active or grace tick. The last active
  tick assigns `ceil(tuning.modes.graceS * tuning.tickRateHz)` grace ticks without consuming a new one.
  Zero configured grace goes directly idle. The last grace tick goes idle. Idle calls are no-ops.
  Return a stable numeric transition (`none`, `activeEnded`, `graceEnded`) without allocating an event.
- An eligibility helper may report whether a RUNNING, idle caller with autoTrigger and a full meter is
  eligible to request LIFTOFF. It must be read-only and must not choose meter storage/consumption, same-tick
  production ordering, repeat-mode policy or manual input. Do not add it if its input/API cannot stay this narrow.
- Resetting/recreating a clock starts idle. Pause is absence of advancement; there is no elapsed-time catch-up.
  No extension, star, COSMONAUT, OVERDRIVE, SMASH, AIR, landing, UI event IDs or policy flags in this slice.

## Acceptance and verification

1. Default boundaries: 300 full active advances, then 60 full grace advances, then idle. A newly created
   timer is not retired by its start call; transition emission occurs exactly once at each boundary.
2. One-tick active/grace, zero grace, schema-valid fractional durations with ceil conversion, repeated
   start attempts, long idle calls, reset, no-step pause and interleaved independent clocks.
3. Independent reference/state-machine checks over varied validated durations, with assertions for
   integer/nonnegative counters, mutual exclusion and exact total active/grace tick counts.
4. Appropriate typecheck/lint/format/full unit/sim checks. Existing golden and both determinism results
   remain unchanged; do not regenerate expected values. Verify no live imports/wiring or production
   outcome changes. Independent QA owns acceptance; original author cannot self-approve.
5. Publish a small draft PR with the exact limitation: internal timing support only, not a playable mode.
   Existing cross-engine CI validates the unchanged game; do not claim it exercises this unwired helper
   unless a separate meaningful cross-engine check is actually added and run.
