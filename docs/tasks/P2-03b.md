# P2-03b — Score completed close passes

Owner: sim engineer · Reviewers: independent QA and orchestrator · Phase: 2 · Depends on: P2-03a

## Goal and scope

Produce actual NEAR MISS events for GDD §9: a close forward overtake earns 50 base points, 10 meter and
one streak action using existing tuning. Own packages/sim, packages/content, shared tuning schema/tests,
focused browser tests, replay fixtures and this card's evidence/docs. Shared event numbers below are frozen.
No new dependencies, models, mode/pickup/HUD systems, server, accounts, rankings or deferred tuning changes.
The stable phone preview is separate and must not be updated.

## Frozen contract

- Append ScoreReason.nearMiss=11 and SimEventKind.nearMiss=26 without renumbering existing values.
  Numeric payload a=vehicle type, b=slot; decoded nearMiss carries vehicleType and slot. The slot is only
  an event-time identifier: presentation cannot dereference it after director reuse.
- Add one persistent Uint8Array per traffic slot for pass state, allocated with traffic. Define explicit
  idle/passing/qualified/disqualified/awarded values. Hash the full persistent state of active slots; reset
  on spawn assignment, removal and reuse. No absolute-z history. Transient completion scratch is cleared
  every step and cannot leak across interleaved sessions.
- Proposed default is a completed, untouched forward pass, at most once per vehicle lifetime. Gate the
  new producer with scoring.nearMissEnabled=true in tuning, record the unresolved policy bundle as Q27
  in DECISIONS and GDD under AGENTS §14. This is a proposed default, not owner approval. false must
  disable events/points and leave all pre-existing physical outcomes unchanged.
- Use current lane-space unrotated boxes. Lateral surface gap is abs(playerX-vehicleX) minus combined
  half-widths. Eligible gap is inclusive 0 through collision.nearMissLateralM (existing .6 m). Require
  simultaneous strictly positive longitudinal and vertical body overlap. Exact roof-plane contact
  with no vertical body overlap is ineligible; low airborne side passes can qualify.
- Arm on a fresh forward player-front crossing of the vehicle rear. Remember a close alongside interval;
  emit only when player rear clears vehicle front. Do not arm merely because a newly initialized vehicle
  is already overlapping alongside. Whole entry/exit in one tick must work. Returning wholly behind
  cancels a pending pass; a failed/wide pass can retry after separation. An awarded vehicle stays spent.
- Clip linear relative start/end trajectories against the alongside interval, vertical-overlap interval
  and either lateral corridor. Zero slopes and open/closed interval endpoints must be explicit. A swept
  body penetration disqualifies even if endpoint-only physical collision code missed it; this rejects
  an award without changing collision outcomes. No guessed substeps, epsilon tuning, transcendentals
  or per-tick allocation. Current traffic has fixed lateral lane centres; taxi motion is future work.
- Capture pre-contact end motion after updateRide and before resolveCollisions. Invalidate the exact slot
  on body contact, HOP/ride start, existing ride or CLEAR directly in producer branches; do not infer slot
  identity from decoded events. Road touchdown alone does not invalidate an unrelated side pass.
- Finalize surviving completions after all collisions and before scoreTick in ascending slot order.
  Terminal crash suppresses all new nearMiss emissions. An unrelated-slot scrape may coexist with a
  valid near miss, then existing settlement rules lose the pot; no global reordering of physics events.
- Current motor traffic filter is vehicle.top !== 'none'; exclude cones/barriers, document this current
  content assumption. Preserve every original raw event and scoring producer order. Extend the ledger
  aggregation to 11 reasons. Update the capacity proof: the prior conservative 554 bound plus at most
  64 raw near events, 64 milestones and two credit buckets is 684, still below allocation 1024.

## Acceptance criteria

1. Mirrored left/right, exact .6 and just outside, exact tangency and penetration, varied widths; close
   only mid-pass then wide at exit, between-frame corridor crossing, whole one-tick pass, receding/zero
   relative speed and direction reversal. Longitudinal and vertical intervals must overlap in time.
2. Low airborne valid; above-roof/roof plane invalid; no CLEAR/HOP/ride/scrape duplicates. Diagonal swept
   penetration earns nothing. Late crash suppresses; unrelated-slot scrape uses existing pot loss.
3. One award/lifetime, failed-pass retry, removal/reuse, origin shift, new run/Retry, interleaved sessions,
   future-affecting state hash differences and deterministic multi-slot ordering. Flag off is covered.
4. Actual default tuning gives base 50 / meter 10 / N+1 / timer 150, correct multiplier/cap/milestones and
   later bank. Existing centre-lane driving gaps exceed .6; never retune widths/lanes to force awards.
5. Add scenario G23 and actual-input replay plus browser close-pass evidence (no injected sim state).
   Compare all physical fields/source events against the scoring baseline on goldens and 10,000 ticks;
   new score/state hashes must have an explained cause. Update all goldens, BOTH fixtures, tuning hash
   and Sim changelog; retain SIM_VERSION 1 only under ADR-024. Never weaken prior tests.
6. Typecheck, lint, format, unit/sim, build/size, independent QA and exact-head cross-engine CI. Browser
   scheduling must respect the one-active-heavy-browser slot; distinguish emulation from a real phone.
